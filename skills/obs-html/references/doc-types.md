# 문서 유형 (obs-html 1·3·6단계)

유형은 **구조와 색을 한 번에 정하는 묶음**이다. 1단계 인터뷰에서 고르고, 3단계 개요는
그 유형의 골격에서 출발하며, 테마 후보도 그 유형의 추천 팔레트에서 낸다. 색은 나중에
바꿀 수 있지만 골격과 전용 블록은 유형을 따른다.

| 유형 | 독자가 원하는 것 | 첫 화면 | 전용 블록 | 추천 팔레트 (앞이 권장) |
|---|---|---|---|---|
| 강의/튜토리얼 | 따라 하며 배운다 | 강의 소개 + 학습 목표 | `.no`, `.goals`, `.lab` | 기술: `vignelli` `freddie` `arctic-frost` · 비기술: `andy` `freddie` `botanical-garden` |
| 리포트/보고서 | 결론을 보고 판단한다 | 결론(`.verdict`) + 핵심 지표(`.kpis`) | `.verdict`, `.kpis` | `press` `tufte` `ocean-depths` |
| 분석 | 무엇이 왜 그런지 근거로 확인한다 | 분석 범위 + 발견 요약 | `.finding` | `shannon` `fuller` `modern-minimalist` · 밝은 바탕: `vignelli` |
| 정리/요약 노트 | 나중에 다시 찾아본다 | 한 장 요약(`.tldr`) | `dl.terms` | `tufte` `knuth` `arctic-frost` `forest-canopy` |

공용 블록(`.tldr`, `.note`, 표, 탭, 접기, 단계 넘김 그림 …)은 어느 유형에서나 쓴다.
전용 블록은 그 유형에서만 쓴다. 리포트에 `.lab`을 넣지 않는다.

## 강의/튜토리얼

독자가 끝까지 따라 하면 무언가를 할 수 있게 된다. 한 강은 "목표 → 설명 → 실습" 한 바퀴다.

```
강의 소개 — 누구를 위한 강의인지, 다 듣고 나면 무엇을 할 수 있는지, 준비물
1강 … N강 — 각 강: 학습 목표 → 개념 설명 + 그림 → 코드 → 실습
흔한 실수 · 팁
마무리 — 강별 한 줄 요약, 다음에 볼 것
참고 자료
```

- 강 번호는 진짜 순서다. 앞 강을 모르면 뒤 강을 못 따라오게 짠다. 순서가 없으면 강의가 아니라 정리다.
- 강마다 `.goals` 하나, `.lab` 하나. 실습은 독자가 직접 칠 명령과 기대 결과까지 적는다.
- 확인 문제가 필요하면 `details.more`로 "정답 보기"를 만든다.

```html
<h2 id="l1"><span class="no">1강</span>설치와 환경</h2>
<div class="goals">
  <b>이 강에서 배울 것</b>
  <ul><li>…</li></ul>
</div>
…
<div class="lab">
  <b>실습</b>
  <ol><li>…</li></ol>
</div>
```

`.no`는 한국어 라벨("1강", "부록")만 쓴다. `LESSON 01` 같은 대문자 눈썹 라벨은 쓰지 않는다.

## 리포트/보고서

읽는 사람은 의사결정자다. 결론을 먼저 말하고, 근거는 뒤에서 확인할 수 있게 둔다(두괄식).

```
결론 — 한두 문장 + 권고 (.verdict)
핵심 지표 — 숫자 2~4개 (.kpis)
배경 — 왜 이 보고서를 썼나, 범위와 방법
본론 — 발견별 근거 (그림·표)
권고안 — 표: 무엇을 / 누가 / 언제
위험과 한계
참고 자료
```

- `.verdict`는 문서에 하나, 맨 앞에. 결론이 없으면 리포트가 아니라 분석이나 정리다.
- `.kpis`의 숫자는 출처가 있는 값만. 숫자 밑 라벨은 "무엇을 잰 값인지"를 적는다.
- 리포트에서는 `.tldr` 대신 `.verdict`를 쓴다. 둘을 함께 두지 않는다.

```html
<div class="verdict">
  <b>결론</b>
  <p>…</p>
</div>
<ul class="kpis">
  <li><span class="v">94%</span><span class="k">평가 통과율 (n=120)</span></li>
</ul>
```

## 분석

코드·시스템·장애·데이터를 파고든다. 독자는 주장마다 근거(파일 위치, 로그, 수치)를 확인하고 싶어 한다.

```
분석 범위 — 대상, 버전·커밋, 방법, 다루지 않는 것
발견 요약 — 발견 목록과 심각도 (표)
구조 — 대상의 전체 그림 (핵심 그림)
발견 1 … N — 각 발견: 현상 → 근거 → 원인 → 영향 (.finding)
가설과 검증 — 표: 가설 / 확인 방법 / 결과
개선 제안
참고 자료
```

- 발견마다 `.finding` 하나. 심각도는 `data-level="high|mid|low"`로 색을 주고, 글자 라벨(높음·중간·낮음)을 함께 쓴다. 색만으로 뜻을 전하지 않는다.
- 근거는 `.where`에 `파일:줄`이나 명령으로 적는다. 근거 없는 발견은 넣지 않는다.

```html
<div class="finding" data-level="high">
  <b>발견 1. …</b><span class="lv">높음</span>
  <p>…</p>
  <p class="where"><code>call_ai_agent/eval/run.py:42</code></p>
</div>
```

## 정리/요약 노트

나중에 다시 찾아볼 문서다. 처음부터 끝까지 읽기보다 훑고 찾는다. 짧은 단락, 표, 용어 정의가 중심이다.

```
한 장 요약 — 요점 3~5개 (.tldr)
핵심 개념 — 개념별 짧은 설명 + 그림
용어 — dl.terms
비교 — 표
자주 쓰는 것 — 명령·코드 조각 모음
참고 자료
```

- 문단은 2~3문장으로 짧게. 같은 내용은 표 하나로 모은다.
- 용어 정의는 `dl.terms`로 묶는다. 용어 3개 미만이면 본문에서 풀어 쓴다.

```html
<dl class="terms">
  <dt>Case</dt><dd>입력 하나와 기대 결과를 묶은 평가 단위</dd>
</dl>
```
