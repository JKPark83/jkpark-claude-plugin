# 다이어그램 디자인 (obs-html 5단계)

> 출처: [cathrynlavery/diagram-design](https://github.com/cathrynlavery/diagram-design)
> (MIT, © 2025 Cathryn Lavery)의 편집 디자인 원칙·커넥터 규칙·복잡도 예산을
> obs-html 환경(오프라인·한국어·라이트/다크 자동 전환)에 맞게 옮겼다.
> 원본과 달리 **Google Fonts를 쓰지 않고**, 색은 hex 대신 페이지 CSS 변수를 쓴다.

목표는 "예쁜 그림"이 아니라 **한 번 보고 이해되는 그림**이다. 대부분의 허접한
그림은 요소가 너무 많고, 모든 박스가 똑같이 생겼고, 선이 사선으로 엉키고,
라벨이 선 위에 겹쳐 있다. 아래 규칙은 전부 이 네 가지를 막기 위한 것이다.

---

## 1. 철학 — 빼는 것이 가장 좋은 수다

- 노드 하나는 **서로 다른 생각 하나**다. 늘 붙어 다니는 두 노드는 하나로 합친다.
- 선 하나는 **정보 하나**를 실어야 한다. 배치만 봐도 관계가 보이면 선을 지운다.
- 강조색은 **깃발이 아니라 편집자의 손가락**이다. 그림당 1~2개 요소에만 쓴다.
  5개에 칠하면 신호가 사라진다.
- 그림은 다 채웠을 때가 아니라 **더 뺄 게 없을 때** 완성이다.
- **목표 밀도 4/10.** 노드가 9개를 넘으면 그림 두 개(개요 + 상세)로 나눈다.

그리기 전에 한 문장으로 답한다: **"이 그림을 본 독자는 무엇을 깨닫는가?"**
그 문장이 그대로 `figcaption`이 된다 (6절). 답이 "섹션이 허전해서"면 그리지 않는다.

그리지 말아야 할 것: 항목 나열(→ 표·목록), 단순한 전/후 비교(→ 표 또는
`html-template.md`의 전/후 비교), 도형 하나짜리 그림(→ 그냥 문장).

## 2. 타입 고르기

먼저 **독자가 이해해야 하는 행동**을 보고, 그다음 배치 문법(타입)을 고른다.
한 그림에 레이아웃 문법은 하나만. 두 개가 필요해 보이면 주된 축을 고른다.

| 보여주려는 것 | 타입 | 배치 문법 |
|---|---|---|
| 구성 요소와 연결 | **아키텍처** | 계층(프런트→백엔드→데이터)이나 신뢰 경계로 묶는다. 흐름은 좌→우 *또는* 위→아래 하나만. 경계는 점선 영역, 영역은 최대 3개 |
| 분기가 있는 판단 로직 | **플로차트** | 모양이 종류를 말한다: 둥근 끝(`rx=20`)=시작/끝, 사각=단계, 마름모=판단(출구 ≤3). 위→아래. 판단의 모든 출구에 라벨 |
| 시간 순서의 메시지 교환 | **시퀀스** | 참여자 ≤5, 세로 생명선, 위→아래가 시간. 응답은 점선 |
| 상태와 전이 | **상태 머신** | 상태 = 둥근 사각, 전이 화살표마다 조건 라벨. 시작점은 작은 채운 원 |
| 층층이 쌓인 추상화 | **레이어 스택** | 폭이 같은 가로 띠 4~6개. 왼쪽에 번호 태그, 가운데 이름, 오른쪽에 설명. 강조는 논의 중인 층 하나 |
| 부모 → 자식 | **트리** | 깊이 ≤4. 형제는 같은 높이에 정렬, 연결선은 직각 |
| 포함 관계(범위) | **중첩** | 안쪽으로 들어갈수록 좁아지는 사각형. 라벨은 각 테두리 왼쪽 위 |
| 시간 위의 사건 | **타임라인** | 가로축 하나 + 위/아래로 번갈아 붙는 사건. 날짜는 축 쪽에 |
| 부서·역할을 넘나드는 절차 | **스윔레인** | 레인 ≤5. 레인 이름은 왼쪽 고정 열, 손 넘김은 레인 경계를 가로지르는 화살표 |
| 두 축으로 위치 매기기 | **사분면** | 축 이름 양 끝에 낮음/높음. 항목 ≤12. 강조는 결론 사분면 하나 |
| 집합의 겹침 | **벤** | 원 ≤3. 겹친 영역 라벨이 핵심 |
| 순위·전환 감소 | **피라미드/퍼널** | 층 ≤6. 퍼널이면 각 층에 수치 |
| 반복해서 강화되는 순환 | **루프** | 원형 배치 단계 3~6개 + 가운데 누적 허브(선택) |
| 원인 여러 개 → 결과 하나 | **피시본** | 뼈대 ≤6, 뼈대마다 하위 원인 ≤3 |
| 한 사람의 단계별 경험 | **사용자 여정** | 단계 ≤6 열 × 행동/감정 행. 불편 지점 표시 ≤2 |

수치 비교(막대·선·산점도)는 이 표가 아니라 **`dataviz` 스킬**을 읽는다. 다만
색·글꼴은 아래 3절 토큰을 따른다.

어디에도 안 맞으면 가장 가까운 것을 골라 변형한다. 새 문법을 즉흥으로 만들지 않는다.

## 3. 토큰 — 색은 페이지 CSS 변수로만

`assets/template.html`의 `:root` 토큰과 **다이어그램 클래스(`.dg`)**가 페이지
`<style>`에 이미 들어 있다. SVG는 인라인이라 페이지 변수를 그대로 물려받으므로, 라이트/다크가
**자동으로** 바뀐다. SVG 안에 `fill="#..."`처럼 색을 직접 쓰지 않는다.

### 노드 종류 → 처리 (모양이 같아도 역할이 다르면 다르게 보이게)

| 노드 종류 | 클래스 | 채우기 / 선 |
|---|---|---|
| **초점** (그림당 1~2개) | `n-focal` | accent 옅은 채움 / accent 선 |
| 처리 단계 · 서비스 · API | `n-step` | surface / ink 선 |
| 저장소 · 상태 | `n-store` | ink 5% / muted 선 |
| 외부 시스템 · 클라우드 | `n-ext` | ink 3% / ink 30% 선 |
| 입력 · 사용자 | `n-input` | muted 10% / soft 선 |
| 선택적 · 비동기 | `n-opt` | ink 2% / ink 20% 점선 |
| 보안 · 경계 영역 | `n-zone` | ink 2% / rule 점선 (영역 테두리, `rx=10`) |

모든 박스가 같은 모양이면 위계가 사라진다 — 가장 흔한 "AI 그림" 증상이다.

### 텍스트 클래스

| 클래스 | 크기 | 용도 |
|---|---|---|
| `t` | 13px 600 | 노드 이름 (한국어 OK) |
| `t-sub` | 12px | 부가 설명 — 포트·경로 같은 **라틴 값은 `mono` 추가** |
| `t-tag` | 10px 600 | 노드 왼쪽 위 종류 태그 — **라틴 약어만** (`API`, `DB`, `S3`). 한글 태그는 `t-sub` |
| `t-edge` | 12px | 화살표 라벨 |
| `t-zone` | 12px 600 | 영역 이름 |
| `mono` | — | 식별자·명령·URL에만. 사람 읽는 이름엔 쓰지 않는다 |
| `c` | — | 가운데 정렬 (`text-anchor: middle`) |

한글 규칙: **12px 미만으로 줄이지 않는다.** 안 들어가면 글자를 줄이지 말고 이름을
줄인다. 영문 다이어그램처럼 대문자·자간 넓힌 라벨을 한글에 흉내 내지 않는다.

### 선과 화살표

| 클래스 | 용도 |
|---|---|
| `e` | 기본 연결 (muted) — `marker-end="url(#{fig}-arr)"` |
| `e-focal` | 핵심 경로 (accent) — `url(#{fig}-arr-a)` |
| `e-link` | 외부 호출·HTTP (`--ext` 청록) — `url(#{fig}-arr-l)` |
| `e-dash` | 응답·비동기·선택 경로 (점선) |

## 4. 커넥터 규칙 — 어기면 무조건 실패

1. **직각 연결만.** x나 y가 같지 않은 두 노드는 반지름 8의 둥근 직각 꺾임으로
   잇는다. 사선 `<line>`은 실패.
   ```svg
   <!-- 오른쪽→아래로 꺾기: (x1,y1)→(x2,y2), mid=(x1+x2)/2 -->
   <path class="e" d="M x1,y1 H mid-8 Q mid,y1 mid,y1+8 V y2-8 Q mid,y2 mid+8,y2 H x2"
         marker-end="url(#f1-arr)"/>
   ```
   목적지가 위/아래에 있으면 박스의 **위/아래 변**으로 드나든다 (옆구리를 뚫지 않는다).
2. **라벨은 선 위가 아니라 선 옆에.** 라벨 뒤에 `class="mask"` 사각형(페이지 배경색)을
   깔고, 마스크 아래 끝과 선 사이에 **6~10px 틈**을 둔다. 세로 선이면 옆으로 같은 틈.
3. **선끼리 겹치지 않는다.** 평행한 두 선은 12px 이상 떨어뜨린다. 교차가 불가피하면
   덜 중요한 선에 반원 점프를 넣는다: `H cx-8 a 8,8 0 0,1 16,0 H x2`.
4. **한 변에 선 여러 개면 붙는 점을 나눈다.** 변 길이 L에 N개면 k번째는
   `L·k/(N+1)` 위치. 인접 간격 ≥12px.
5. **끝점이 아닌 박스 뒤로 지나가지 않는다.** 돌아간다. 정말 불가능할 때만 점선으로
   통과시키고 라벨은 보이는 쪽 끝에 둔다.
6. **라벨 마스크가 나중에 그려지는 노드와 겹치지 않는다.** 그리는 순서는
   배경 → 영역 → 선 → 라벨 → 노드이므로, 노드와 겹친 라벨은 잘려 보인다.

## 5. 배치 규격

- 캔버스 폭 **760** (`viewBox="0 0 760 H"`), `<svg class="dg">`. 폭·높이는 템플릿 CSS가
  준다 (`width:100%; height:auto`). `height="auto"` 속성은 무효 — 150px로 뭉개진다.
- 모든 좌표·크기·간격은 **4의 배수**. 노드 사이 간격 24/32/40/48, 박스 안 여백 12/16.
- 노드 높이: 한 줄 48, 이름+부가설명 60, 태그까지 72. 모서리 반경 6 (영역은 10).
- **그림자 금지.** 테두리로 층을 나눈다. `rx` 12 이상의 둥근 알약 박스 금지.
- 범례가 필요하면 그림 **아래 가로 띠**로 (구분선 + 한 줄). 그림 영역 안에 띄우지 않는다.
  범례는 실제로 쓴 종류만.
- **모바일 폭**: 가로로 5개 이상 늘어선 흐름은 390px 화면에서 글자가 6px로 줄어든다.
  - 핵심 그림 → 세로형 변형을 하나 더 그려 `fig-wide` / `fig-narrow`로 전환
    (`html-template.md` "반응형 그림").
  - 보조 그림 → `<div class="fig-scroll">`로 감싸 좁은 화면에서 가로 스크롤.

### 한글 라벨 폭 계산 (눈대중 금지)

**글자 단위로** 더한다: 한글·전각 문자 = 1em, 그 밖의 문자(영문·숫자·공백·기호)
= 0.6em (mono는 0.62em). 합계 × 글자 크기 + 좌우 여백 16×2 → 4의 배수로 올림.

예: `주문 v2.1` (13px) = 한글 2자(2em) + `␠v2.1` 5자(3em) = 5em = 65px → 65+32=97 → **100**.
"한글 몇 자 + 영문 몇 자"로 **문자 종류별로 세면 숫자·기호를 빼먹는다.**

`scripts/check_html.py`가 박스 안 라벨이 넘치는지 이 산식으로 검사한다.

## 6. 접근성·캡션 계약

```html
<figure>
  <svg class="dg" viewBox="0 0 760 240"
       role="img" aria-labelledby="f1-title f1-desc">
    <title id="f1-title">요청 처리 흐름</title>
    <desc id="f1-desc">브라우저 요청이 CDN을 거쳐 API 서버에 닿고, 캐시가 없을 때만 DB를 조회하는 흐름.</desc>
    <defs>
      <marker id="f1-arr" viewBox="0 0 10 10" refX="9" refY="5" markerWidth="7" markerHeight="7"
              orient="auto-start-reverse"><path class="arr" d="M0,1 L10,5 L0,9 z"/></marker>
      <!-- 필요할 때만: f1-arr-a (class="arr-a"), f1-arr-l (class="arr-l") -->
    </defs>
    <!-- 영역 → 선 → 라벨 → 노드 순서 -->
  </svg>
  <figcaption><b>그림 1.</b> 캐시가 맞으면 DB까지 가지 않는다 — 출처: 직접 작성</figcaption>
</figure>
```

- `<title>`은 `<svg>`의 **첫 자식**, `<desc>`는 그다음. 둘 다 채운다.
- `id`는 그림마다 접두사(`f1-`, `f2-` …). 마커 id도 마찬가지 — 겹치면 두 번째
  그림의 화살표가 첫 그림 색으로 그려진다.
- `<desc>`는 **모양이 아니라 내용**: "상자 다섯 개가 있다"(X) → "요청이 CDN을 거쳐…"(O).
- **캡션은 라벨이 아니라 주장이다.** "그림 1. 캐시 구조"(X) →
  "그림 1. 캐시가 맞으면 DB까지 가지 않는다"(O). 독자가 그림에서 가져가야 할
  한 문장이 캡션이다. 1절의 "무엇을 깨닫는가" 답을 그대로 쓴다.

## 7. 복잡도 예산

| 한도 | 값 |
|---|---|
| 노드 | ≤9 |
| 화살표 | ≤12 |
| 강조(accent) 요소 | ≤2 |
| 영역(경계) | ≤3 |
| 시퀀스 참여자 | ≤5 |
| 스윔레인 레인 | ≤5 |
| 트리 깊이 | ≤4 |
| 사분면 항목 | ≤12 |

넘치면 개요 + 상세 두 장으로 나눈다. 단계별로 보여주고 싶으면 한 장에 다 그리고
`html-template.md`의 **단계 넘김 그림**으로 순서를 부여한다.

## 8. AI 티 나는 그림 (안티패턴)

| 증상 | 왜 나쁜가 |
|---|---|
| 모든 박스가 같은 모양·색 | 위계가 사라진다 |
| 박스마다 그림자, 알약처럼 둥근 모서리 | 결정 없이 "있어 보이게"만 한 것 |
| 다크 배경 + 네온 청록/보라 발광 | "기술적"으로 보이려는 기본값 |
| 사선 화살표, 선 위에 얹힌 라벨 | 선을 따라갈 수 없다 |
| 그림 안에 떠 있는 범례 | 노드와 부딪힌다 |
| 강조색을 "중요한 것" 전부에 | 신호가 사라진다 |
| 세로쓰기 라벨 | 읽을 수 없다 |
| 본문을 그대로 도형으로 옮긴 그림 | 그림이 새 정보를 주지 않는다 |
| Mermaid 자동 배치를 흉내 낸 레이아웃 | 편집 판단 없이 자동 간격을 들여온 것 |

## 9. 그리기 전·후 체크 (취향 게이트)

**그리기 전**
- [ ] "독자는 무엇을 깨닫는가" 한 문장이 있다 (→ 캡션)
- [ ] 표나 문단으로 같은 일을 할 수 없다
- [ ] 타입 하나를 골랐고 예산 안이다

**빼기 테스트**
- [ ] 지워도 이해되는 노드가 없다 / 합칠 두 노드가 없다
- [ ] 배치로 이미 보이는 관계에 선을 긋지 않았다
- [ ] 색·모양으로 이미 드러나는 라벨을 또 쓰지 않았다

**기술**
- [ ] 강조 ≤2, SVG 안에 hex 색 없음, 그림자 없음
- [ ] 직각 연결, 라벨-선 틈 6~10px, 겹치는 선 없음, 붙는 점 분산
